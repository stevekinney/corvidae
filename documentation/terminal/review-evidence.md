## How to use the tables

Each row is one task in one browser. The coverage map shows where each item of the issue's criteria is recorded. Record Observed as what VoiceOver actually spoke or what you saw, in your own words. Outcome is exactly `pass` or `fail`. A `fail` is a finding: describe it, and when it is fixed record the fix SHA and re-review the row at that SHA in a new row suffixed `.r2`, `.r3` (for example `T2-S.r2`) rather than overwriting the first result. Screenshot references are file names under `documentation/terminal/review-screenshots/`, named after the row, for example `T2-S.png`. Crop the start token out of any screenshot that shows the address bar.

A finding is blocking when it makes a required task impossible, misleading, or inaccessible with VoiceOver, loses or rewrites input, steals focus, or sends unintended bytes. Every blocking finding is fixed in source and re-reviewed at the new SHA. No required task is waived or turned into a follow-up.

## Pre-identified findings for the reviewer

These are things the packet's author saw while building the review controls. They are observations to confirm or reject, not verdicts: the decision, outcome and any fix SHA are yours and are blank below. Both were seen in Chromium through Playwright, not with VoiceOver.

### Finding A: real backpressure cannot be held

A process that stops reading its input does not leave the terminal parked in `Backpressure: input paused`. The session ends as `Terminal failed` after about two seconds, which matches the host's input acknowledgement deadline (2 s, expiry is unknown delivery) in [`security-and-budgets.md`](./security-and-budgets.md). A large paste into a busy command therefore ends the session instead of pausing it.

Repro in the example app:

- Start the server and open `Login shell`.
- Type `stty raw -echo; sleep 60` and press Enter. This makes the shell's child stop reading input and stop echoing.
- Copy about 60,000 characters of single-line text (for example `yes | head -c 60000 | pbcopy`; the paste limit is 65,536 bytes and a single line skips the paste review) and paste it into the terminal.
- Expected by the specification: `Backpressure: input paused`, output stays readable, and the terminal returns to `Connected` when capacity is acknowledged.
- Seen in preparation: `Connected` for about two seconds, then `Terminal failed`, and the session does not return.

Preparation status: COR-1540 changed the host to hold the input instead of failing the session, and the example now reaches the state for real with the `Stalled input` profile and `Copy a long line` (paste, then read `Backpressure: input paused`; the terminal returns to `Connected` when the program reads again after 20 seconds). `Inject backpressure` is gone. Re-check this row against that fix.

### Finding B: Cancel in backpressure has nothing to cancel

The specification used to say `Cancel` in `backpressured` "cancels unsent operations; output remains readable." The client queues nothing: while backpressured it refuses input locally, so there are no unsent operations. The example therefore left the session alone when `Cancel` was activated in `backpressured`, and the button appeared to do nothing.

Repro in the example app:

- Reach `Backpressure: input paused` with the `Stalled input` profile (see Finding A).
- Look for `Cancel`.
- Decision taken (COR-1540): `Cancel` is not offered in `backpressured`. The client queues no unsent operation, so there is nothing to cancel, and the row in `experience.md` was amended to match. Output stays readable.
- Seen in preparation, before the change: `Cancel` did nothing, or ended the session and showed `No terminal session` and no output.

## Inherent full-screen accessibility limits

DRAFT FOR STEVE TO CONFIRM OR EDIT. This text is a proposal assembled from the repository documentation, not an accepted statement. It is not approved until the reviewer edits it and signs the Acceptance block. Each bullet names its source; any claim that VoiceOver behavior has not been observed is marked and should be confirmed or struck during the review.

The terminal does not claim parity with a native terminal emulator or with a screen reader's dedicated terminal support. These limits are inherent to rendering a character-cell screen in a web page.

- A full-screen program (an editor, a pager, a program on the alternate screen) redraws cells in place. The page has a screen of characters and a text-input surface, not a document, so there is no heading, list, or table structure for VoiceOver to navigate, and the position of the program's cursor is not a navigation target the page can announce. Source: `terminal.a11y.md` (the engine supplies the screen, the selection, and the text-input surface). Confirm by observation in X6 and X10.
- The page does not announce every byte or every redraw. Output announcement is off by default (`announceOutput`), bounded, polite, and throttled, so a program that repaints continuously is not read live. Source: `terminal.a11y.md`, `experience.md` ("never emitted for every output byte").
- The accessible alternative is a frozen, bounded snapshot: at most 64 KiB, newest content kept, plain text with soft wraps joined. It is not live, it does not preserve color, cursor position, or two-dimensional layout, and the alternate screen is searched and exported on its own because only the active buffer is retained. Source: `components/terminal/README.md`. Confirm in T3.
- Bare Escape is shell input, so it cannot also be a universal "leave the terminal" key. Leaving key capture is `Ctrl+Shift+Escape`, and with capture off Tab moves through the page. While capture is on, Tab and Shift+Tab belong to the program. Source: `experience.md`, `components/terminal/README.md`. Confirm in X3 and X10.
- Reserved browser, operating-system, and assistive-technology chords (`Cmd+L`, `Cmd+T`, `Cmd+W`, `Cmd+Tab`, and the VoiceOver modifier `Ctrl+Option`) always belong to their owners and cannot be sent to a program. Source: `experience.md` conflict matrix.
- While a program has mouse reporting on and capture is on, the pointer reports to the program instead of selecting text; selection then needs a modifier (Shift, or Option on a Mac). Mouse reporting is off by default. Source: `components/terminal/README.md`. Confirm in X4.
- Links are off by default, and only visible HTTPS text may be offered. A hidden OSC 8 destination, a path, a command scheme, or a download is never offered, so a reader cannot reach those destinations from the terminal. Source: `experience.md`, `terminal.a11y.md`.
- Search is literal and case-sensitive over the active buffer, bounded to 256 code points of query and 1 MiB of text, with no normalization. Source: `components/terminal/README.md`.
- Input method composition and dead keys depend on the browser and operating system delivering committed text; the package does not infer characters from physical keys. Windows, NVDA, interactive mobile behavior, tabs, splits, shell integration, and path opening are outside v1. Source: `experience.md`; the extension ledger lists NVDA with Chrome.
- Whether VoiceOver reads the engine's retained rows as expected, and how VoiceOver behaves while a program repaints, has not been observed by the packet's author. These are the open questions the review answers.
