# CI replay and accounting

A failing targeted or pull request job retains a small structured replay record independently of the aggregate receipt. The record names the run, attempt, job, head, base, checked tree and toolchain, together with the command, bounded selection and the first recognized assertion's matcher and source location. Assertion values and raw diagnostics are omitted. If an identity, assertion, JUnit report or trace is unavailable, the record says why rather than substituting a success.

Download a run's replay artifacts with `gh run download <run-id> --pattern 'replay-*' --pattern 'playwright-interborough-*'` and inspect `ci-replay-record.json`. Check out its recorded revision in a disposable worktree, install the recorded Bun version and frozen dependencies, restore its named selection parameters, and run its recorded command. When `CI_REPLAY_NO_CREDENTIALS` is `true`, remove provider and cache credentials from the replayed command's environment. When `CI_REPLAY_CREDENTIAL_BOUNDARY` is `producer-scrubbed`, the Turbo scheduler retains cache credentials and the browser producer removes them before starting tests. Browser replays use the recorded Playwright image and a hosted runner of the matching architecture. The sanitized JUnit file retains test-case outcomes without names, attributes or diagnostic text. Raw browser traces are not retained. Fixture screenshot jobs retain only actual PNGs for the existing baseline tool.

The accounting command keeps immutable provider responses in a private directory. It reads workflow runs created in the half-open UTC interval `[from, until)`, records its selection before fetching job details, and joins landed revisions to run attempts and distinct provider job IDs. Direct provider pull-request associations take precedence; otherwise a run is assigned only when its commit has one owner. Ambiguous and unmatched runs remain separate. Pull-request commit inventories truncated by the provider are completed from local Git only when the landing has one parent, the recovered count matches the provider count, and every returned provider commit appears in the recovered set. An unreconciled inventory makes the command fail.

To reproduce the fixed cohort from its retained snapshots, set `CI_ACCOUNTING_EVIDENCE_DIRECTORY` to the private snapshot directory and run:

```bash
CI_ACCOUNTING_MAIN_SHA=fb1a2cd2daf87dbc7211fe7c9f4d8d6ae7e2a23d bun scripts/ci-run-accounting.ts --repo stevekinney/corvidae --from 2026-11-01T00:00:00Z --until 2026-11-23T22:00:00Z --json
```

The directory contains raw provider responses and must not be published. The JSON projection contains only the selected identities and measured fields. A new directory fetches provider data; an existing one reuses each captured response. `CI_ACCOUNTING_SELECTION_ONLY=1` records the selection without job requests, and `CI_ACCOUNTING_PLAN_ONLY=1` reports the attribution plan and minimum detail-request count.

Execution seconds come from provider job start and completion timestamps, not from charged minutes. Skipped jobs and missing, invalid or reversed timestamps do not contribute to observed duration percentiles. Per-revision summaries cover only directly or unambiguously attributed runs whose selected attempts have observable jobs; they are not total cost for a change when other work remains unmatched. Queue eligibility, cache provenance, billed units, storage, rates, human time and agent spend are unknown when the provider evidence does not establish them. Accounting never establishes delivery eligibility: in particular, a canceled run cannot satisfy a delivery obligation.

## Fixed-cohort report

The window from November 1 at 00:00 UTC to November 23 at 22:00 UTC in 2026 contains 2,815 observed workflow runs. The selected population is 2,159 runs: 1,645 Main or Pull request runs and 514 Targeted checks runs. Selection completed at 02:04 UTC on November 24; attempt and job snapshots were collected subsequently, so this is not an atomic provider snapshot. The pinned main history contains 971 landed revisions under the selection method above. It attributes 1,220 runs; 133 runs have ambiguous owners and 806 remain unmatched. Those 939 runs are excluded from attributed totals, not assumed free. Of the 971 revisions, 500 have no attributed run in this window.

The 1,220 attributed runs contain 1,229 observed attempts: 469 push, 445 pull request and 315 manual dispatch attempts. There are 358 successful first attempts, nine retry attempts, 337 failed attempts, 526 canceled attempts, 365 successful attempts and one queued attempt. Supersession is unknown for all 1,229 attempts; cancellation alone does not prove it.
