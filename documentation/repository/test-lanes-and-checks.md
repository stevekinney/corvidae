# Test lanes and documentation checks

The detail behind AGENTS.md "Commands". The rules stay in AGENTS.md; this file holds the mechanics and history.

The `test:benchmarks` commands are the workspace-scoped entries in that list, because each belongs to a single package and `bun run --filter` is how the root invokes one workspace's script. `bun run test` excludes what they run: a suite that asserts a wall-clock or memory target measures the machine as much as the code, and on a host running several agents at once those measurements swing far enough that they cannot gate validation. They record numbers on demand instead. Their targets are unchanged. A root lint guard, `scripts/check-wall-clock-assertions.ts`, fails the build when a `*.test.ts` outside `scripts/benchmarks/` asserts an upper bound on a duration or a rate it can derive from a timing reading.

Every library and component documents its exported surface. Its `lint` runs `scripts/check-documentation-coverage.ts`, which follows each entry in the workspace's `exports` map to the declaring symbol and fails when that symbol has no documentation comment. It judges exports, not their members, and skips symbols another workspace declares and Svelte components, which Cinder's component metadata documents. `testing/*` and applications are out of scope. Exports that were undocumented when the check arrived are listed in each workspace's `documentation-coverage-allowlist.json`, which can only shrink: a new undocumented export fails, and so does an entry for an export that is now documented or gone. Run `bun ../../scripts/check-documentation-coverage.ts --shrink` from the workspace to drop stale entries; `--seed` refuses to run once the file has entries. Document a new export rather than adding it to the list.

Every library and component also type-checks the examples in its Markdown. Its `typecheck` runs `scripts/check-documentation-code-blocks.ts` (as `typecheck:documentation`), which compiles each ` ```ts ` or ` ```typescript ` fence in the workspace's Markdown, outside dependencies and generated output, as its own module under the workspace's `tsconfig.json`. Fences in other languages, `svelte` included, are not checked. Imports of the workspace's own name resolve through its entry in `scripts/published-exports.json` when that entry is an exports map, so a guide cannot import what the mirror does not publish, and through its `package.json` `exports` otherwise; other workspaces resolve as they do for any consumer. One fence attribute may follow the language: `file=<name>.ts` names a block so a later block in the same document can import it relatively. Any other attribute fails, and no attribute skips a block: every TypeScript example is checked. Give an example the context it needs instead, through imports, short `declare` lines for values the reader supplies, or an earlier `file=` block. Write a signature as code that references the real export, so drift in the export breaks it, and type a third-party client the workspace does not install against a small structural interface the package's real API must accept.

Correctness assertions never move with them. Weft keeps its benchmark directory's unit tests in the default suite, and Markdown's pathological-document and diff-identity checks stayed behind in `src/` when its timing assertions left. Each package excludes its benchmarks in the way its layout allows: Weft path-ignores the `.test.ts` benchmark files under `scripts/benchmarks/` in its `test` script and also keeps `*.bench.ts` files there, run by explicit `test:benchmarks` entries; Markdown and Ventriloquist name theirs `*.bench.ts` under `scripts/benchmarks/`, which Bun's default discovery skips on its own. The rule is the same everywhere: a target that depends on host load belongs outside the gate, and the correctness it was bundled with belongs inside it.

A test that does seconds of real work (spawning processes, bundling, git, ts-morph, instrumented loops) is a different class: its assertion is correctness, so it stays in the gate, but it sits near Bun's 5-second per-test limit and host contention pushes it over (COR-1499). Such a test either becomes fast by removing redundant work, or moves to a `*.slow.test.ts` file. A workspace's `test` ignores those files (`--path-ignore-patterns='**/*.slow.test.ts'`, or the playground runner's own lane split) and its `test:slow` runs only them; the root package's lanes are `test:self` and `test:self:slow`. `bun run validate` runs `bun run test:slow` with `--concurrency=1` after the fast phase, so nothing leaves the gate and no timeout is raised. A workspace that holds `*.slow.test.ts` files must define both scripts, and `scripts/check-test-durations.ts` fails `bun run validate` otherwise.

Each workspace's fast `test` runs through `scripts/bun-test-junit.ts` (the playground through `scripts/run-tests.ts`), which writes JUnit XML to `test-output/junit/`. A per-test time budget depends on host load, which AGENTS.md keeps out of the gate, so it is enforced on demand, the way `test:benchmarks` is: `bun run check:test-durations` fails any fast-lane test that took longer than 2 s unless `scripts/test-duration-allowlist.json` lists it, and fails an allowlisted entry that is gone or took under 1 s, so the list can only shrink. The script first reruns every report-writing task with `bun run measure:test-durations` (`turbo run test:self test test:browser-fixtures --force`, covering the root reports and each package's `test`), because turbo replays cached reports; run it on a quiet host. `bun run validate` runs `bun run report:test-durations` instead, which prints the same findings as warnings and exits 0; only wiring problems (a workspace bypassing the wrapper, or holding slow files without their lane scripts) fail it. `bun scripts/check-test-durations.ts --shrink` drops stale entries, and `--seed` refuses to run once the file has entries. Adding an entry is a reviewed edit and needs a tracking issue. Process spawns inside test bodies are a separate rule with its own guard (COR-1507); the duration check also sees the in-process work that guard cannot, such as ts-morph analysis and per-byte loops, and a test that a spawn fix makes fast leaves the allowlist through the stale-entry rule. Never raise the budget.
