# Cinder Responsive Layout Policy

Component-owned responsive behavior should use container queries. If a component changes because its own inline size is constrained, the stylesheet should set `container-type: inline-size` on the component root and query that container.

Viewport queries are reserved for viewport-owned behavior: app shells, drawers, and modality switches where the viewport itself is the constraint. The documented exceptions share one set of breakpoints: phones are narrower than 640px, tablets run from 640px to 1023px, and desktops start at 1024px.

- Sidebar's mobile Drawer switch (`SIDEBAR_MOBILE_BREAKPOINT`, `639.98px`), so tablets keep the inline column and its icon rail.
- Table's `stackBelow`, which stacks the rows of a table with controls into cards. It is not viewport-owned: the length is compared in script against the table's own container width (a `ResizeObserver` on the scroll box), because a size container query cannot read a length from a prop. The viewport stands in only until the container has a measurable width.
- Modal's and ConfirmDialog's `sheetBelow`, which dock every dialog as a bottom sheet on a narrow screen. Both default to 760px (`DIALOG_SHEET_BREAKPOINT`, wider than the phone breakpoint: a 32rem card on a 640px to 759px screen leaves too little either side), so a form modal and a confirmation share one presentation. The rule reads the viewport, not a container, because a dialog opens in the top layer and has no sized ancestor.
- Popover's, Dropdown's, Combobox's, and MultiSelect's `sheetBelow`, which open them as bottom sheets on a phone.
- Tabs' optional `collapseBelow` (off by default), which turns a horizontal tab bar into one select. It is a phone-form choice made in script (`useViewportBelow`), so what is not shown is not in the page.
- Breadcrumbs' `collapseBelow`, which collapses a trail to a back link to the parent and the current page on a phone. It is chosen in CSS, not in script, so the first paint is already the right form (COR-2770): both forms are in the server HTML, and a viewport `@media` rule in `breadcrumbs.css` shows one, keyed to the trail's length (`data-cinder-phone-below`). A length other than the default 640px brings the same rules in an inline `<style>`, as Sidebar's `mobileBreakpoint` does for its server fallback.
- Tabs' and SegmentedControl's fit. They are not viewport-owned: Tabs collapses into a select (`collapseOnOverflow`), and SegmentedControl stacks into a radio list, only when the options do not fit the room the component has, measured in script as FilterBar measures its row (content width against the container's width, remembered while the narrow form hides it). Three short tabs stay a bar on a phone.
- StackedListItem's phone form. It is not viewport-owned: below 640px of the row's own width a status moves to line two beside the kind and agent (a container query on the row, `@container cinder-stacked-list-item (max-width: 639.98px)`), and two or more trailing `actions` collapse into one menu button (one action stays a compact button; chosen in script, because CSS cannot swap the controls, from a `ResizeObserver` on the row). A row narrower than 448px is inside that range, so main's own-width 448px arrangement for a status-first row is the same rule and has no block of its own. A 360px pane in a 1280px window takes the phone form; a wide column in a narrow window does not. The shared `phoneViewport` in `phone-viewport.svelte.ts` stands in only until the row has a measurable width (the server, a test with no layout).
- JsonEditor's long lines: a line longer than the frame scrolls sideways inside the editor with the gutter fixed, and below 640px it wraps instead, because sideways scrolling is hard to use on a phone. CodeMirror's line wrapping is an editor setting rather than a stylesheet rule, so the component reads the shared `phoneViewport` and passes it in; `wrap` overrides it either way.

Each choice made in script reads the viewport through `useViewportBelow` in `viewport-below.svelte.ts` (or the shared `phoneViewport`, for the row), which wraps Svelte's `MediaQuery`, so it adds no viewport `@media` rule to component CSS. A form that must be right on the first paint is chosen in CSS instead, as Breadcrumbs' is, and its viewport `@media` rule is listed in `scripts/platform-viewport-baseline.json`.

Quality checks for responsive components should include both cases:

- a narrow component container inside a wide viewport
- a wide component container inside a narrow viewport
