The dashboard verifies worker contracts. Workers → worker detail and System → Registry → workflow detail each compare a connected worker's accepted manifest with the registry's active revision and show, as text, every workflow revision, version, or contract-hash difference and every activity the worker is missing, adds, or declares with a contract hash that differs from the registry, showing the worker's and the registry's activity hashes side by side. Like `weft worker verify`, the dashboard derives each expected activity hash from the registry's schema pair with Weft's own `activityContractHash`. Both surfaces render copyable `weft codegen --from <path> --out <file>` and `weft worker verify --manifest <path> --from <registry.json>` commands with file names derived from the worker's deployment and build and the snapshot's registry version. A failed task whose error is a strict payload-boundary rejection (`WorkerJsonValidationError`) is called out in the task ledger with the rejected path, separately from a contract mismatch.
